# 3분 제출 영상 대본

## 0:00–0:25 · 문제와 공개 경계

기업 화면의 `C 150`, `P 100`을 가리키며 원금액은 기업 측 비공개 입력이라고 설명합니다. 상단 증거 흐름선의 “금액 비공개 → 증명 작업 → 공개 원장”을 따라가며 원장에는 기간·승인·커밋먼트만 남는다고 말합니다.

## 0:25–1:15 · 1기 정상 승인

네트워크 pill이 `Midnight 원장 · undeployed`인지 확인한 뒤 `1기 · 정상 자료`에서 `검증하고 원장에 기록`을 누릅니다. queued/proving/submitting/confirming 상태는 서버 작업 상태이며 연출 타이머가 아님을 짚습니다. 완료되면 공개 검증 증거의 operation ID와 transaction ID를 보여주고 은행 보기에서 1기 승인만 확인합니다.

## 1:15–2:05 · 2기 현금 부족

기업 보기로 돌아와 `2기 자료 등록`을 누릅니다. 현재 기간은 2기, 승인된 기간은 1기로 분리되는 것을 보여줍니다. `2기 · 현금 부족`을 검증해 `INSUFFICIENT_CASH`가 나오고 transaction ID가 생성되지 않음을 확인합니다.

## 2:05–2:35 · 이전 자료 재사용 차단

`1기 · 이전 자료`를 선택해 검증합니다. `STALE_DATA` 거절과 2기/승인 1기 원장 불변 상태를 보여줍니다. 과거 승인이 현재 승인으로 표시되지 않는 점을 은행 보기에서 확인합니다.

## 2:35–3:00 · 기술 증거

터미널에서 `pnpm phase5:verify`의 회로 30건, API 10건, HTTP E2E, secret scan 통과 결과를 짧게 보여줍니다. 마지막 화면은 계약 주소, 마지막 실제 transaction ID, 공개 commitment가 보이는 원장 상세로 끝냅니다.

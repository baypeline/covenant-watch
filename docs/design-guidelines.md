# Covenant Watch 디자인 가이드

이 문서는 Covenant Watch의 화면과 문구를 설계할 때 사용하는 기준입니다. 색상 구현의 기준 파일은 [`src/styles/GlobalStyles.tsx`](../src/styles/GlobalStyles.tsx)입니다.

## 제품과 화면의 역할

- 대상: 금융약정 준수 여부를 제출하는 기업 담당자와 결과를 확인하는 금융기관 담당자
- 핵심 작업: 원금액을 공개하지 않고 현재 기간의 약정 충족 여부를 확인하거나 요청합니다.
- 화면 원칙: 한 화면에는 하나의 주된 판단과 하나의 주된 행동만 둡니다.
- 고유한 표현: 화면을 장식적인 Web3 대시보드가 아니라 **약정 업무 원장**으로 보이게 만듭니다.
- 메인 히어로는 `금융약정 검증 서비스`를 제목에서 가장 크게 표시하고, 대상 사용자와 비공개 검증이라는 차별점은 한 단계 낮은 위계로 설명합니다.
- 메인 히어로는 헤더를 제외한 `100dvh`를 채웁니다. 작동 방식은 자료 등록, 회사 요청, 비공개 검증, 결과 기록을 스크롤 순서에 맞춰 설명합니다.
- 히어로의 대표 오브젝트는 금융기관이 받는 검증 결과서입니다. 실제 금액 대신 조건 충족 여부와 원장 기록만 보여 서비스의 정체성을 시각적으로 설명합니다.
- 히어로의 제목, 차별점, 행동은 첫 진입 시 짧은 간격으로 한 번만 등장하며, 반복하지 않습니다.
- 작동 방식에서는 화면 한쪽의 기록 예시를 고정하고, 사용자가 각 설명에 도달할 때 해당 기록만 전환합니다. 실제 계약이 검사하거나 기록하지 않는 내용을 시각화를 위해 만들지 않습니다.

## 경험 원칙

토스에서는 시각적 스타일이나 말투가 아니라 다음 UX 원칙만 참고합니다.

1. 사용자가 지금 해야 할 일을 먼저 보여줍니다.
2. 선택지는 이해 가능한 단위로 줄이고, 기술 상세는 필요할 때 펼칩니다.
3. 요청 접수, 증명 생성, 거래 제출, 원장 확정을 실제 상태 그대로 구분합니다.
4. 오류에는 원인과 다음 행동을 함께 제시합니다.
5. 화면을 새로고침해도 진행 중인 작업을 다시 찾을 수 있게 합니다.

친근함을 위해 해요체를 사용하지 않습니다. 본문은 간결한 평서형 `~합니다`를 사용하고, 버튼은 행동을 나타내는 명사형 또는 짧은 동사형으로 작성합니다.

| 피할 표현 | 사용할 표현 |
| --- | --- |
| 약정을 확인해요 | 약정 확인 |
| 자료를 불러오고 있어요 | 자료를 확인하고 있습니다 |
| 다시 시도해 주세요 | 다시 시도 |
| 조건을 충족하지 못했어요 | 현재 자료로는 약정을 충족하지 못했습니다 |

## 페이지 구성

역할 전환은 한 화면 안의 탭 상태가 아니라 App Router의 독립된 페이지로 구성합니다.

| 경로 | 사용자 | 한 가지 핵심 작업 |
| --- | --- | --- |
| `/` | 모든 사용자 | 제품의 목적을 이해하고 자신의 작업으로 이동합니다. |
| `/request` | 기업 담당자 | 검증 목적과 공개되는 정보를 이해합니다. |
| `/request/select` | 기업 담당자 | 현재 기간의 재무 자료를 선택합니다. |
| `/request/review` | 기업 담당자 | 선택 내용과 공개 범위를 확인하고 검증을 요청합니다. |
| `/status` | 금융기관 담당자 | 공개 원장에 확정된 현재 기간의 약정 상태를 확인합니다. |

루트 `/`는 제품의 핵심을 설명하는 히어로 페이지입니다. 모든 페이지는 공통 헤더를 사용하지만 각 페이지에는 한 가지 작업만 둡니다. 원장 주소와 거래 ID는 기본 판단을 방해하지 않도록 결과 화면의 접힌 상세 영역에 둡니다.

모든 페이지는 동일한 헤더와 푸터를 사용합니다. 푸터에는 제품의 핵심 문장과 `검증 요청`, `결과 확인` 링크만 두며, 본문에서 이미 설명한 기술 정보나 형식적인 링크 목록을 반복하지 않습니다.
헤더와 푸터에는 포인트 선을 사용하지 않습니다. 대신 `--color-chrome`의 옅은 Ledger Blue 계열 배경으로 본문과 공통 영역을 구분합니다.

## 화면 구조: 약정 업무 원장

일반적인 SaaS 대시보드의 큰 소개 영역, 카드 그리드, 상시 보조 패널을 사용하지 않습니다. 각 페이지는 사용자가 다루는 한 건의 약정을 중심으로 구성합니다.

- 페이지 제목은 제품 홍보 문구가 아니라 사용자가 지금 이해하거나 수행할 일을 가리킵니다.
- 결과 페이지의 제목 옆에는 현재 판단에 필요한 상태 하나만 표시합니다.
- 현재 기간, 승인된 기간, 마지막 확인 시점을 페이지 상단의 동일한 위치에서 확인할 수 있게 합니다.
- 속성은 카드가 아니라 키와 값으로 구성한 문서형 행에 표시합니다.
- 기업 담당자의 요청 흐름은 안내, 자료 선택, 요청 확인의 세 페이지로 나눕니다.
- `/request`는 결과만 공개된다는 핵심을 먼저 설명하고, 검증 기준과 공개 범위는 접힌 항목으로 둡니다.
- `/request/select`에서는 자료 선택 외의 판단을 요구하지 않습니다.
- `/request/review`에서는 회사 내부 금액을 다시 보여주되, 외부에 공개되는 정보는 별도로 명시합니다.
- `/status`는 결과 안내, 약정 정보, 최근 원장 기록 순서로 배치합니다.
- 실제 데이터가 없는 처리 이력, 지표, 증명서 장식은 만들지 않습니다.

구조적 참고 자료:

- [Modern Treasury · Designing Our New UI](https://www.moderntreasury.com/journal/behind-the-scenes-designing-our-new-ui): 업무 객체와 정확한 데이터 중심의 금융 운영 화면
- [GOV.UK · Summary list](https://design-system.service.gov.uk/components/summary-list/): 키와 값으로 사실을 전달하는 문서형 정보 구조
- [Companies House · Filing history](https://find-and-update.company-information.service.gov.uk/company/00000006/filing-history): 기록을 날짜, 유형, 설명 단위로 조회하는 공공 원장 구조

## 시각 방향: Paper & Slate

라이트 모드는 선명한 흰 계약서와 잉크를, 다크 모드는 검은 동굴이 아닌 청회색 서류함과 작업대를 모티프로 사용합니다.

정체성을 만드는 기본색은 다음 다섯 가지입니다.

- Paper White `#FFFFFF`: 계약서와 주요 표면
- Paper Fog `#F3F6F7`: 구획과 읽기 보조 표면
- Ink `#1C242B`: 라이트 모드의 본문과 판단 정보
- Filing Slate `#30373D`: 다크 모드의 편안한 주요 표면
- Ledger Blue `#2D657A`: 확인, 선택, 주요 행동

보라색·청록색 그라데이션, 네온, 글로우, 유리 효과, 순수 검정 배경은 사용하지 않습니다. 상태색은 브랜드 장식이 아니라 결과 전달에만 사용합니다.

## 테마 동작

기본값은 운영체제의 `prefers-color-scheme` 설정을 따릅니다. 사용자가 테마를 직접 고른 경우 루트 `html` 요소에 속성을 설정합니다.

```html
<html data-theme="light">
<html data-theme="dark">
```

- 속성이 없으면 시스템 설정을 따릅니다.
- `data-theme="light"`는 시스템 설정과 관계없이 라이트 모드를 사용합니다.
- `data-theme="dark"`는 시스템 설정과 관계없이 다크 모드를 사용합니다.
- 테마 선택 UI를 추가할 때 선택값을 브라우저에 저장하되, 첫 렌더링에서 깜빡임이 없도록 문서 렌더링 전에 적용합니다.

## 색상 사용 규칙

- 주요 행동은 화면 또는 작업 단계마다 하나만 강조합니다.
- 라이트 버튼은 Ledger Blue 위에 흰색 텍스트를, 다크 버튼은 밝은 Ledger Blue 위에 짙은 잉크색 텍스트를 사용합니다.
- 카드 구분은 얇은 테두리와 표면색 차이를 우선하며, 그림자는 낮은 불투명도로 제한합니다.
- 주소, 해시, 블록 번호는 보조 텍스트로 표시합니다. 기술 정보라는 이유만으로 강조색을 사용하지 않습니다.
- 다크 모드에서는 `#000000`과 순백색 본문을 사용하지 않습니다.
- 주요 본문, 보조 본문, 버튼 조합은 WCAG AA 대비를 유지합니다. 입력 경계와 포커스 링은 인접 배경과 3:1 이상의 대비를 목표로 합니다.

## 타이포그래피와 정보 구조

- 제목과 본문: `Pretendard Variable`. 큰 제목도 과장된 영웅 문구보다 현재 판단과 작업을 설명하는 데 사용합니다.
- 데이터와 식별자: `ui-monospace`, `SFMono-Regular`, `monospace`. 금액, 해시, 계약 주소처럼 실제 데이터에만 사용합니다.
- 영문 대문자와 넓은 자간은 시스템 상태나 기술 라벨을 장식하는 용도로 반복하지 않습니다.
- 기업 화면은 요청할 자료와 주요 행동을 먼저, 금융기관 화면은 현재 기간과 충족 결과를 먼저 보여줍니다.
- 원장 주소와 거래 증거는 기본 정보 아래의 점진적 공개 영역에 둡니다.

## 형태와 움직임

- 모서리 반경은 컨테이너 계층을 구분하는 정도로만 사용합니다. 모든 요소를 알약 형태로 만들지 않습니다.
- 아이콘은 기능 식별에 필요할 때만 사용하며 방패, 지문, 데이터베이스 아이콘을 장식적으로 반복하지 않습니다.
- 진행 애니메이션은 실제 상태 변화를 설명할 때만 사용합니다. 분위기를 위한 반복 애니메이션은 넣지 않습니다.
- 키보드 포커스를 항상 표시하고 `prefers-reduced-motion`을 존중합니다.

## AI 슬롭 방지 기준

AI 슬롭은 특정 색상이나 컴포넌트 하나가 아니라, 제품에 근거하지 않은 익숙한 장치가 여러 개 겹칠 때 발생하는 것으로 봅니다.

- 모든 내용을 카드에 넣지 않습니다. 독립적으로 이동하거나 구분해야 하는 단위에만 컨테이너를 사용합니다.
- 카드 안에 다시 둥근 카드를 중첩하지 않습니다. 간격과 구분선으로 먼저 위계를 만듭니다.
- 한 요소에 테두리, 그림자, 색조 배경, 강조 띠를 동시에 적용하지 않습니다.
- blur·glass·glow는 사용하지 않습니다. 그림자는 실제로 떠 있는 요소에만 제한합니다.
- 일반 라벨을 알약 모양 배지로 만들지 않습니다. 배지는 상태나 필터처럼 짧고 분류 가능한 값에만 사용합니다.
- 큰 제목 옆에 지나치게 작은 본문을 두지 않습니다. 보조 정보도 실제 사용 환경에서 읽을 수 있는 크기를 유지합니다.
- 아이콘은 텍스트를 대신하는 장식이 아니라 행동이나 상태를 명확히 할 때만 사용합니다.
- 로딩, 빈 상태, 실패, 권한 없음, 좁은 화면을 정상 화면과 함께 설계합니다.
- 두 번째 페이지에서도 제목 크기, 행동 이름, 상태 색, 간격이 같은 의미로 유지되는지 확인합니다.
